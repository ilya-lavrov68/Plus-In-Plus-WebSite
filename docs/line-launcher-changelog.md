# История версий Line Launcher на сайте

Страница `/line-launcher/changelog` показывает релизы продукта так, как они описаны
в репозитории `ilya-lavrov68/Line-Launcher`. Это витрина фактов, а не второй
источник правды: тексты не переписываются и не придумываются.

## Откуда данные

| Источник в GitHub | Что берём |
| --- | --- |
| `CHANGELOG.md` | версия, дата, вступление, разделы «Добавлено / Изменено / Исправлено» и пояснения |
| Теги (`/tags`) | тег версии (`v0.10.0`), если он проставлен |
| Релизы (`/releases`) | ссылка на релиз и файлы сборки, если релиз опубликован |

Важно: пока у продукта **нет опубликованных GitHub Releases** — история живёт в
`CHANGELOG.md`, теги ставятся по мере готовности сборки. Поэтому на странице нет
кнопок «Скачать»: скрипт просто не найдёт ассетов, а сайт не обещает того, чего нет.
Как только релизы появятся, файлы автоматически подтянутся в карточку версии.

## Команды

```bash
npm run changelog:sync     # перечитать GitHub и перезаписать content/line-launcher-changelog.json
npm run changelog:check    # проверить, что файл данных совпадает с GitHub (ничего не пишет)
```

Скрипт делает четыре запроса к публичному API GitHub. Токен не обязателен: лимита в
60 запросов в час на IP достаточно. Если задан `GITHUB_TOKEN` в окружении, лимит
выше; токен читается только из переменной и никогда не сохраняется в файл данных.

## Что лежит в файле данных

`content/line-launcher-changelog.json` (коммитится, чтобы сайт не зависел от сети):

- `entries[]` — релизы от свежего к старому: `version`, `date`, `intro[]`,
  `sections[]` (`kind`: `added` / `changed` / `fixed` / `removed` / `security` /
  `note`, `title`, `items[]`, `paragraphs[]`), `release` (тег, ссылка, ассеты);
- `latestVersion`, `latestDate` — для бейджа «Последняя версия»;
- `changelogSha` — commit sha файла `CHANGELOG.md` на момент синхронизации;
- `changelogUrl`, `tagsUrl`, `releasesUrl` — ссылки «источник» на странице.

Парсер понимает только реальный формат файла:

```markdown
## 0.15.4 — 2026-11-17

Короткое описание релиза.

### Добавлено

- **Что появилось.** Подробности.
```

Заголовок без версии (например, «Как выбирается номер») считается методичкой и
пропускается — он попадает в `skippedHeadings`. Незнакомый заголовок раздела
сохраняется как есть с видом `note`, поэтому пояснения автора («Почему это не в
конфиге провайдера», «Устойчивость») не теряются.

## Порядок выпуска новой версии

1. В репозитории Line Launcher обновить `version.json` и `CHANGELOG.md`, поставить
   тег `vX.Y.Z` (и опубликовать релиз, если есть установщики).
2. В этом репозитории выполнить `npm run changelog:sync` и закоммитить
   `content/line-launcher-changelog.json`.
3. Обновить версию в статусе продукта: `messages/{ru,en}.json` → `lineLauncher.status`
   и `lib/work-cases.ts` (факт «Статус»). Тест `tests/changelog.test.cjs` падает,
   пока эти строки расходятся с последней версией в данных.
4. Проверить страницу `/line-launcher/changelog` в RU и EN, прогнать `npm test`.

## Что показывает страница

- бейдж последней версии, количество версий и дату свежего релиза;
- поиск по изменениям и фильтр по типу правки (добавлено / изменено / исправлено);
- список версий слева с подсветкой той, что сейчас на экране;
- якорную ссылку на версию (`#v0-15-4`) и кнопку «Ссылка на версию»;
- ссылки «источник»: `CHANGELOG.md`, теги, релиз;
- в английской версии — honest-плашка о том, что записи ведутся на русском
  и показываются без перевода.

## Ограничения

- Разметка записей — минимальный inline-markdown: `**жирный**`, `` `код` ``,
  ссылки. Полный markdown не нужен, а HTML из репозитория на сайт не попадает.
- Относительные ссылки из `CHANGELOG.md` (`docs/LOGGING.md`) ведут в GitHub:
  на сайте таких файлов нет.
- Страница не делает запросов к GitHub во время просмотра: данные лежат в
  репозитории, поэтому сайт работает без внешней сети и без токена.
