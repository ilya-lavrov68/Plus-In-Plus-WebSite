# Публикация продукта из админки

Продукт студии (Line Launcher и всё, что появится после него) публикуется из
панели: `/admin/studio-products`. Ни сборки, ни правки кода, ни деплоя для
новой страницы продукта не нужно.

## Как добавить продукт

1. `/admin/studio-products` → «Новый продукт».
2. Заполнить имя и slug. Slug — адрес страницы: `/products/<slug>`.
3. Добавить строку о продукте и описание на двух языках (RU/EN).
4. Указать репозиторий: `https://github.com/владелец/репозиторий` и файл истории
   версий (`CHANGELOG.md` по умолчанию).
5. Поставить «Опубликован» → сохранить.

После этого продукт сразу появляется в меню шапки («Продукты») и получает
страницу по шаблону.

## Шаблон страницы

`app/(site)/products/[slug]/page.tsx` → `components/site/product-template-view.tsx`.

Порядок секций повторяет эталон продуктовой страницы:

1. Первый экран: имя, строка о продукте, кнопки «Обсудить проект», репозиторий,
   загрузка (если указана), статус, версия, факты.
2. «Что нового» — три последние версии из репозитория и ссылка на релизы.
3. «Что это» — описание продукта.
4. Призыв к обсуждению.

Если у продукта уже есть своя страница с более богатой вёрсткой (Line Launcher,
`/line-launcher`), поле «Свой адрес страницы» указывает на неё: продукт остаётся
в меню, но ведёт по своему адресу. Шаблон в этом случае не используется.

## Откуда берётся история версий

Кнопка «Синхронизировать историю версий» в карточке продукта читает GitHub:

| Источник в GitHub | Что берём |
| --- | --- |
| `CHANGELOG.md` | версия, дата, вступление, разделы, пояснения |
| `/tags` | тег версии (`v1.2.0`), если проставлен |
| `/releases` | ссылка на релиз и файлы сборки, если релиз опубликован |

Разбор тот же, что у `npm run changelog:sync` для Line Launcher: один парсер
(`scripts/lib/changelog-parse.mjs`), поэтому формат `CHANGELOG.md` для всех
продуктов одинаковый:

```markdown
## 0.15.4 — 2026-11-17

Одна строка о смысле релиза.

### Добавлено

- **Что-то.** Подробности.
```

Четыре запроса на продукт к публичному API GitHub. Токен не обязателен; если в
окружении есть `GITHUB_TOKEN`, лимит выше. Токен нигде не сохраняется.

Результат складывается в `studio_products.changelog_json` вместе с датой
синхронизации: страница продукта показывает «Что нового» из этой копии, а не
ходит в GitHub на каждый запрос посетителя.

### Синхронизация: сейчас и потом

Сейчас — по кнопке: владелец публикует релиз в репозитории и нажимает
«Синхронизировать». Если позже понадобится автоматика, есть два очевидных пути
без изменения модели данных:

* вебхук GitHub (`release` / `push`) → тот же `fetchStudioChangelog`, но
  запускаемый по событию;
* cron (раз в сутки) по списку продуктов с заполненным `repo_url`.

Оба варианта пишут в ту же таблицу и тот же JSON, поэтому страница и админка
менять не придётся.

## Публикация и снятие

* «Опубликован» — единственный переключатель видимости. Сняли — страница отдаёт
  404, продукт исчезает из меню шапки.
* Флаг ставится и в карточке (галочка), и одной кнопкой из списка.
* Все действия пишутся в журнал активности (`activity_logs`), публиковать
  может только ADMIN/FOUNDER.

## Где что лежит

| Файл | Роль |
| --- | --- |
| `db/schema.sql` | таблица `studio_products` |
| `lib/studio-products.ts` | чтение, запись, адрес страницы продукта |
| `lib/studio-product-sync.ts` | чтение репозитория: changelog, теги, релизы |
| `app/(admin)/admin/studio-products/` | список, форма, действия админки |
| `components/admin/studio-product-form.tsx` | одна форма для создания и правки |
| `components/site/product-template-view.tsx` | шаблон страницы продукта |
| `components/site/navbar.tsx` | меню «Продукты» из опубликованных записей |

## Обновление базы

Таблица `studio_products` появилась позже остальных, поэтому приложение создаёт
её само при первом обращении (`lib/studio-products-schema.ts`): `CREATE TABLE IF
NOT EXISTS` плюс добавление поздних колонок. Отдельного шага после обновления не
требуется, а `npm run dev` дополнительно применяет `db/schema.sql`, если каких-то
таблиц не хватает.

Ручной путь остаётся и ничего не ломает:

```bash
npm run db:migrate   # применить db/schema.sql (идемпотентно)
npm run db:check     # проверить, что все таблицы на месте
```

Если база открыта только на чтение, страница продукта отдаёт 404, а админка
показывает текст ошибки — без стектрейса.

## Чистая установка

Если в базе нет ни одного опубликованного продукта, меню «Продукты» показывает
статический реестр `lib/products.ts` (Line Launcher). Так шапка не остаётся
пустой до первой публикации; как только продукт опубликован в админке, меню
переходит на данные из базы.
