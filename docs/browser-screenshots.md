# Скриншоты сайта в браузере

Реальные кадры вёрстки нужны для дизайн-проверки: по ним агент и владелец
видят то же, что посетитель, а не только разметку. Комплект собран в
`docs/redesign/screens/` (WebP + `manifest.json`), а снимает его
`scripts/screenshots.mjs`.

## Как получить браузер

В sandbox и на чистой машине системного Chrome может не быть. Восстановление
берёт первый доступный источник и не кладёт тяжёлые бинарники в репозиторий:

```bash
npm run browser:restore   # системный Chromium → кэш → @sparticuz/chromium из npm
npm run screenshots       # прод-сборка + 17 кадров
```

Кэш живёт вне проекта: `~/.cache/pip-site/browser`. Скрипт печатает, что
именно выбрано, и не пишет в `node_modules`.

## Почему снимаем прод-сборку

`npm run screenshots` сам собирает `next build` и поднимает `next start` на
свободном порту. Это не формальность:

- dev-сервер под Turbopack внутри sandbox отдаёт HTML, но клиентская гидрация
  не завершается, и в кадр попадает серверная разметка без сцен, reveal и
  состояния баннера cookies — то есть не то, что видит посетитель;
- прод-страница проверяется целиком: сборка, middleware, CSP, реальные чанки.

Снимать уже запущенный сервер можно явно:

```bash
npm run screenshots -- --base-url http://127.0.0.1:3000 --no-build
npm run screenshots -- --only home-ru        # один маршрут, манифест сохраняется
```

## Что скрипт делает перед кадром

1. **Ждёт гидрацию.** Пока на странице нет React-узлов, кадр бессмысленный:
   скрипт падает, а не сохраняет пустую панель.
2. **Прогревает прокрутку.** Блоки с `data-reveal` появляются через
   `IntersectionObserver`; без прохода по странице полный кадр показывал бы
   дырки на месте секций.
3. **Согласие на cookies.** Баннер перекрывает первый экран, поэтому заранее
   записывается выбор «только необходимые» — аналитика в кадре не участвует.
4. **Маска программного рендерера.** Headless Chromium рисует через
   SwiftShader, а Hazeglow намеренно отказывается от софтверного
   растеризатора (его кадры не укладываются в бюджет анимации). Скрипт
   подменяет только строку `GL_RENDERER`; пиксели по-прежнему считает WebGL,
   и кадр соответствует тому, что видит посетитель с видеокартой.
5. **Ошибки JS.** Любая ошибка страницы или HTTP-ответ ≥ 400 (кроме подсказки
   React DevTools) роняет съёмку: снимок — доказательство, а не декорация.

## Особенности окружения

- **`--disable-gpu-compositing`.** Композитинг через SwiftShader зависает на
  `Page.captureScreenshot`: кадр ждёт готовности поверхности и не дожидается.
  Сам WebGL при этом работает и попадает в снимок.
- **`upgrade-insecure-requests` в прод-CSP.** На локальном http-стенде браузер
  поднимает префетч-запросы до https и получает SSL-ошибку. Скрипт возвращает
  такие запросы на http только для `127.0.0.1`/`localhost`.
- **`allowedDevOrigins` в `next.config.mjs`.** Next отдаёт dev-ресурсы только
  «своим» origin. Если `127.0.0.1` и `localhost` не разрешены, страница в
  dev-режиме выглядит статичной: меню, сцены и баннер не работают. Превью в
  sandbox приходит на `*.e2b.app`, поэтому этот origin разрешён тоже.

## Что не попадает в кадр осознанно

Админка и служебные экраны требуют авторизации; скриншоты публичной части не
подменяют ролевые проверки. Мобильные кадры снимаются с `deviceScaleFactor: 1`:
2× на длинной странице не помещается в лимит кодировщика Chromium.
